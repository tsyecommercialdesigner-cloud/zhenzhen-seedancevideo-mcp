# task-scheduling-recovery Specification

## Purpose

管理共享视频任务从排队到生成结果确认的自动执行与恢复，明确额度、超时、显式管理及异常状态的可观察语义，在多 Host、进程中断和上游结果不确定时避免重复提交和虚假终态。

## Requirements

### Requirement: 自动闭环与独立额度

系统 SHALL 在后端运行期间自动推进排队、提交、轮询和下载，区分接收、生成成功与产物就绪；生成、样片、成片和独立超分任务共用总额度，轮询和下载独立限制并发。

#### Scenario: 生成成功
- **WHEN** 可靠确认远端生成成功
- **THEN** 持久化结果并释放生成额度后进入下载，不提前报告产物就绪；额度只释放一次。

#### Scenario: 未知仍占位
- **WHEN** 任务提交结果不明、查询耗尽或跟踪超时
- **THEN** 继续保留生成占位和托管素材，除非显式放弃或核实生成结束。

### Requirement: 可派发 FIFO 与保护

系统 SHALL 按原入队顺序派发当前可执行任务，跳过被 API 故障保护阻挡的任务但保留其顺序和队列容量，不允许人工插队。

#### Scenario: 局部保护
- **WHEN** 队列 A1、B1、A2、B2 中仅 API A 被保护
- **THEN** B1、B2 可依序派发，A1、A2 保留原顺序；恢复后不抢占已执行任务。

#### Scenario: 保护解除
- **WHEN** 配置修复重启或受支持非付费检查确认恢复
- **THEN** 根据明确依据解除保护，不反复发起付费生成探测；等待保护不消耗提交重试次数。

### Requirement: 提交前持久化与结果不明

系统 SHALL 先可靠记录提交意图和占位再发出请求；可能已发出但缺乏可靠结果时停止重提并记录提交结果不明。

#### Scenario: 响应或落账失败
- **WHEN** 请求可能已发送，超时、断连或收到 task_id 后保存前崩溃
- **THEN** 加入状态不明名单，保留占位与素材及可用关联信息，不伪造 task_id、不自动重提。

#### Scenario: 确认未创建
- **WHEN** 依据已核实上游能力可靠证明未创建任务且 Agent 显式重试
- **THEN** 允许原任务记录新提交尝试；仅查不到不构成证明。

### Requirement: 查询重试耗尽

系统 SHALL 对暂时查询故障有限退避重试，预算耗尽后停止自动轮询并持久化待处理原因、task_id、最后状态及时间。

#### Scenario: 预算耗尽
- **WHEN** 连续查询失败达到预算
- **THEN** 明确提示 Agent，可刷新、恢复或放弃；不判定生成失败、不丢失历史，网络恢复或重启不重置预算。

### Requirement: 分离刷新与恢复

系统 SHALL 本地查询不访问上游，显式刷新只查一次，恢复自动跟踪开启新预算和期限并保留历史。

#### Scenario: 刷新仍生成
- **WHEN** 待处理任务单次刷新得到生成中
- **THEN** 更新事实但不暗启持续轮询，仍等待显式恢复；恢复成功后移出该查询异常名单。

#### Scenario: 刷新获得成功
- **WHEN** 显式刷新包括已放弃任务后确认成功
- **THEN** 释放仍存在的生成占位并自动下载，更新待处理原因为当前阶段，全部必需产物就绪后移出未解决名单。

#### Scenario: 刷新获得失败或取消
- **WHEN** 取得可靠失败或取消终态
- **THEN** 释放占位、移出状态不明名单并触发素材清理，保留原因。

### Requirement: 分离三类超时

系统 SHALL 区分单次请求、工具等待和生成跟踪期限；跟踪从开始提交计时，包含停机但不含本地排队。

#### Scenario: 跟踪到期
- **WHEN** 到达配置期限而生成未确认结束
- **THEN** 不再启动新轮询，允许在途查询在请求时限内收尾；无可靠终态则标记跟踪超时待处理并保留占位、素材和最后状态。

#### Scenario: 等待超时
- **WHEN** Agent 有界等待结束
- **THEN** 返回当前状态和等待超时，不取消任务；显式恢复可以开启新期限。

### Requirement: 重启恢复与额度重建

系统 SHALL 先恢复占位、阶段和历史再派发；待处理及放弃状态不因重启自动恢复。

#### Scenario: 降低额度
- **WHEN** 原占位 5 个而新上限为 3
- **THEN** 保留五个占位和已有任务查询，可用额度为零，不派发新任务直至占用低于上限。

#### Scenario: 恢复不同阶段
- **WHEN** 后端重新启动
- **THEN** 未提交任务保留顺序，已有 task_id 的正常任务恢复查询，成功未下载的恢复下载；跟踪已到期则待处理，重试历史不重置，退避可自然到期。

#### Scenario: 恢复已放弃任务
- **WHEN** Agent 请求恢复已释放占位且未结束的任务
- **THEN** 必须重新取得额度，无额度明确拒绝恢复；单次刷新仍可用。原本保留占位的恢复不得重复占位。

### Requirement: 版本化管理操作

系统 SHALL 同一任务状态变更串行生效，取消、恢复和放弃校验已知状态版本，重复操作不叠加副作用。

#### Scenario: 并发管理冲突
- **WHEN** 恢复与放弃同时竞争且一方状态版本已过期
- **THEN** 后生效操作返回冲突及最新状态，不静默覆盖；重复恢复不新增轮询或重置预算。

#### Scenario: 并发刷新
- **WHEN** 多个 Host 同时刷新同一任务
- **THEN** 合并或复用进行中的查询，不重复发起等价供应商查询。

### Requirement: 取消语义

系统 SHALL 仅在未进入提交阶段时本地取消成功；上游取消必须以明确证据为准，不把取消请求受理当作完成。

#### Scenario: 取消赢得竞争
- **WHEN** 本地取消先于提交意图生效
- **THEN** 不向供应商提交，释放队列容量并触发清理；重复取消不产生新副作用。

#### Scenario: 派发先行
- **WHEN** 派发先于取消或请求处于提交结果不明
- **THEN** 不报告本地取消成功，按当前版本和已核实上游取消能力处理。

#### Scenario: 取消期间生成结束
- **WHEN** 上游取消尚未确认但生成成功
- **THEN** 按真实成功结果下载；取消超时保留不确定性，明确取消成功才释放额度并清理。

### Requirement: 显式放弃与迟到事实

系统 SHALL 显式放弃须提供原因并确认远端可能运行及计费；停止自动处理、释放占位并立即触发素材清理，不冒充失败或取消。

#### Scenario: 放弃未知任务
- **WHEN** Agent 显式放弃尚未核实远端结果的任务
- **THEN** 保留远端未知记录、task_id 和历史，提示释放后远端实际未结束任务数可能超出本地额度。

#### Scenario: 放弃下载
- **WHEN** 生成已成功但下载未完成且 Agent 放弃
- **THEN** 保留生成成功和已就绪产物，仅停止剩余处理并清理输入，不改成远端未知。

#### Scenario: 旧响应迟到
- **WHEN** 放弃已生效后旧查询或提交返回
- **THEN** 可保存可靠 task_id 和事实，但不恢复跟踪、下载或占位；新显式操作才可找回产物。

### Requirement: 存储故障保护

系统 SHALL 共享任务记录无法可靠持久化时停止接收及新生成、下载、清理副作用；可靠核对后才恢复调度。

#### Scenario: 查询结果无法保存
- **WHEN** 远端结果已获取但无法落账
- **THEN** 不据此释放额度、启动下载或清理；返回存储故障，不用内存冒充保存成功。

#### Scenario: 运行中存储失效
- **WHEN** 任务库不可用
- **THEN** 已有请求有限收尾，健康信息显示故障，可可靠读取的状态注明可能滞后，不自动创建空库。

### Requirement: 中断管理调用

系统 SHALL 不因响应未送达回滚已生效管理操作；允许已发出的单次查询有限收尾保存事实。

#### Scenario: 管理响应丢失
- **WHEN** 取消或恢复已执行但 Host 没有收到结果
- **THEN** 可重新查询当前状态与版本决定后续操作，不把通信失败当作操作未执行。


### Requirement: 上游依赖核实边界

系统 SHALL 将下列依赖保持为待核实，取得依据前不宣称支持，且按本规范中不确定或不可用分支处理。

#### Scenario: 接口资料尚未核实
- **WHEN** 相关接口文档或能力证据尚未提供
- **THEN** 以下核实边界继续生效：待核实：可靠未接单证据、幂等／历史核对、取消、限流、完整状态协议及终态稳定性。SUCCESS/completed 为成功、failed 为失败的语义已确认；这不证明兼容端点的字段层级或其他状态。涉及这些能力的分支仅在核实后启用；否则按结果不明、待处理或明确不支持处理，不承诺供应商行为。

### Requirement: 超分及成片复用任务生命周期

系统 SHALL 独立超分和样片转成片使用同一共享排队、额度、持久化、未知处理、取消与恢复规则；不是绕过全局约束的同步捷径。

#### Scenario: 跨工具并发
- **WHEN** 生成与超分同时提交且总额度已满
- **THEN** 两者均按可派发 FIFO 等待，不因独立 tool 另开无限额度；各自返回独立任务 ID。

#### Scenario: 不自动串联
- **WHEN** 样片或普通生成任务成功
- **THEN** 只继续该任务的查询与下载，不自动提交成片或超分；必须有新的显式请求和 request_key。

#### Scenario: 样片排队期间失效
- **WHEN** 成片已入队但派发前已知样片超出有效期
- **THEN** 转需要处理而不发起生成，不自动新建样片；有效期起算点尚未核实时不伪造精确过期判定。

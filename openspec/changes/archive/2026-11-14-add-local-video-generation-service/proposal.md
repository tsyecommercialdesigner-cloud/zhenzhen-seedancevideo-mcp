# Proposal

当前验收状态（2026-11-14）：tasks 为71/71完成；13.1干净Windows安装、13.3实际Host主视频交付及13.4代表性最小矩阵已有证据。完整产物集合仍待核实，主视频就绪不等于全集就绪；Job生命周期调查已关闭，已复现启动器自身Job可终止后端，历史Codex最初终止方式未取证，兼容性限制未修复且不重开排查。范围以 [验证记录](../../../../docs/verification-add-local-video-generation-service.md) 为准；任务完成不代表全部规范无条件满足。

## Why

Agent 需要跨多次调用管理耗时的视频生成，单次 API 封装无法可靠覆盖共享排队、结果查询、中断恢复及视频落盘。本次从零建立 Windows 本地 MCP Server，让同一用户的多个 Agent Host 共享任务后端，在避免重复生成与不确定结果误判的前提下完成从提交到产物交付的闭环。

## What Changes

### 已确认目标与范围

- **本地共享运行**：每个 Host 通过 stdio 接入，同一 Windows 用户共享一个后端、队列、任务库和产物，不做项目权限隔离。最后一个 Host 断开后暂停新生成派发，宽限期内重连则恢复，否则有限收尾退出；下次启动恢复。连接失效可回收，只有确认旧后端退出才能接管，保持调度所有权唯一，不自动强杀或重建空库。
- **统一 API 与接收契约**：首期接入 `https://api.seedance.nz` 的 26 个 Seedance 模型和独立 `zhenzhen-upscaler` 超分工具，以 `api_id` 区分能力契约、以 `model` 区分模型，不将模型数量等同端点数量；默认提交 `POST /v1/video/generations`、查询 `GET /v1/video/generations/{id}`，Bearer API Key 鉴权，不自动切换 `/v1/videos`；提供只读能力查询、无生成副作用的可选预检，正式提交即授权自动执行。正式提交重新校验并固定有效参数。单次提交创建独立任务，必带 `request_key`，跨 Host、跨重启去重；相同请求返回原任务，内容冲突报错，支持按标识找回。队列和素材设可配置上限，必要素材托管及任务持久化完成后才确认入队。
- **队列与自动推进**：后端自动完成排队、提交、轮询、下载。未确认结束的生成任务共用全局额度，轮询与下载另限并发。可派发任务先入先出；受 API 故障保护阻挡的任务保留原顺序和队列容量，其他 API 可继续。配置级上游错误阻止受影响 API 派发。重启先重建占位；降低上限不取消已有任务，待占位下降后再派发。
- **持久化恢复与显式管理**：区分本地接收、供应商生成成功和本地产物就绪。查询、下载有限重试；结果不明、预算耗尽和跟踪超时持久化为待处理，保留已知 `task_id`、事实及历史，不冒充失败。提供本地查询、单次刷新、恢复自动跟踪、下载恢复、取消和显式放弃；恢复使用新预算并保留历史。提交结果不明不自动重提，只有核实未接单后才可显式重试原任务；重新生成使用新请求标识并关联原任务。支持提交前取消，上游取消待核实；工具调用中断不等于取消任务。同任务变更串行生效，重复操作不叠加，冲突通过状态版本返回。
- **素材与产物管理**：本地输入保存托管副本与内容摘要，URL 仅保存引用、不保证可恢复，输入准备阶段不做素材加工。未提交任务只可补回内容一致的副本。产物就绪、明确生成失败、提交前取消、明确上游取消及显式放弃跟踪或下载后，立即触发输入副本清理；其余未完成和结果不明任务保留。清理严格限于托管副本，有限重试且可显式重试；不删除用户原文件、任务记录或生成视频。视频默认长期保留，以本地路径和分页清单交付，不在工具响应传输二进制或 Base64。支持复制到任意有权限的本地绝对路径，或显式工作区基准下的相对路径；相对路径不可越出工作区，默认不覆盖，显式覆盖也须保全旧文件直到新副本就绪。
- **Agent 可观察性**：提供分页列表、异常名单、单任务状态、按已知版本有界等待、健康信息及有界脱敏诊断；首期不依赖主动推送。名单非消费式，多个 Host 均可见。游标分页不承诺跨页快照，单任务响应保持一致。错误返回阶段、稳定错误码、必要摘要、可重试性、建议动作和诊断 ID，不透传堆栈、源码、完整原始日志、密钥或签名 URL，不编造进度百分比。
- **统一配置与网络**：支持 `.env`、进程级及用户级环境变量配置视频输出目录等；API 密钥统一命名为 `ZHENZHEN_SEEDANCE_API_KEY`，不使用通用 `API_KEY` 别名；实际安装目录 `.env` 优先，逐字段缺失时依次回退到进程环境、Windows 当前用户环境，最后使用声明的默认值；空值或非法值不回退。后端统一配置、重启生效，显式冲突只拒绝新接入方，不泄露敏感值。输出目录按任务接收时固定，任务库独立，新目录不迁移旧任务。支持显式代理、绕过规则、自定义可信 CA，默认直连并校验证书，不自动绕过代理或关闭验证，重定向不跨域转发 API 凭据。任务保留非敏感供应商连接身份，同账号换钥可接续，跨账号或端点不盲目接管旧任务。

- **模型规则与样片**：2.0 为两区域 × Standard/Fast/Mini × t2v/i2v/multi 共 18 个；2.5 为两区域各三个常规模型和一个成片模型，共 8 个。按模式校验素材与参数，2.5 i2v 仅 adaptive；2.0 Standard 支持 native4k，2.5 不支持。自动时长使用 `metadata.duration=-1` 并省略 seconds。2.5 样片固定 480p，成片引用本人、同区域、已完成且 7 天内有效的样片，固定 native1080p，不重传提示词或素材；样片与成片是两次独立显式提交，不自动串联。
- **提示词优化授权**：顶层 `enhance_prompt` 初始默认 false。Agent 可在正式提交前询问单次允许或总是允许；总是允许按同一 Windows 用户跨 Host、跨重启持久化并可撤销，单次显式 false 优先。未获授权不开启，接收时固定有效值与授权来源，重试不重算。该授权是可即时修改的业务偏好，不是要求重启的环境配置；不适用于无新提示词的成片和超分请求。
- **独立视频超分**：独立 tool 固定模型 `zhenzhen-upscaler`，输入恰好一个 MP4，目标 720p/1080p/2k/4k、默认 1080p；约 10 分钟上限的精确边界待核实。无需 prompt、seconds 或提示词优化；复用接收、共享额度、恢复、清理和交付机制，不自动在生成后发起付费超分。此能力不同于模型分辨率选项中的超分档。
- **上传与实扣记录**：本地副本先经 `POST /v1/files/upload` 换临时 URL，不能直接作为供应商文件路径输入。上传 URL 的有效期与用户自带 URL 分别处理；已知临时链接过期不等于素材内容改变。只保存供应商实际返回的 `data.usage.amount/currency`，缺失为未返回而非零，按量成片不推导费用公式；费用缺失不阻塞视频下载或引发重新生成。

### 关键成功、异常与边界场景

| 场景 | 已确认结果 |
| --- | --- |
| 正常闭环与跨 Host 接续 | A 提交、B 查询并交付；不重复派发。全部必需产物就绪后生成闭环完成，复制和素材清理的失败独立记录，不撤销生成成功。 |
| 接收竞争与响应丢失 | 同请求最多接收一次；接收中不冒充入队，失败释放预留并清理临时副本。响应丢失按请求标识找回，不换标识重提。 |
| 停机、崩溃与配置变化 | 排队顺序、占位、重试历史及固定输出目录延续；已进入待处理或放弃状态不因重启自动恢复。任务库故障停止新增副作用，核对后再调度。 |
| 请求、等待与跟踪超时 | 三者分别处理；跟踪期限从开始提交计算，包含停机、不包含本地排队。到期在途查询有限收尾，无明确终态则待处理，不判定生成失败。 |
| 提交结果不明 | 保留占位与素材，不自动重提；核实未创建才允许显式重试，不绑定未经核验的 `task_id`。 |
| 查询耗尽与下载失败 | 保留 ID 和历史；单次刷新不暗启持续轮询。确认生成成功即释放生成额度，部分下载保留已就绪文件，仅恢复失败部分；全部产物取得后移出待处理。 |
| 取消、放弃与迟到响应 | 取消与派发串行判断；上游取消受理不等于成功，取消期间生成成功仍下载。放弃释放占位并清理素材；迟到响应可补充可靠事实，但不能恢复执行权限。放弃后可显式找回产物，恢复未结束任务的跟踪须重新取得额度。 |
| 素材清理及视频外部删改 | 清理待办持久化，故障不撤销终态、重启不重置耗尽预算。视频缺失或变更如实标记，显式恢复且不静默覆盖；输入已清理不阻碍仅凭任务 ID 下载。 |
| 路径冲突与复制中断 | 不破坏原产物或已有目标文件，目录链接不能绕过相对路径边界；目标已发布但响应丢失时仍遵守默认不覆盖规则。 |
| 上游、网络与状态异常 | 未知状态、任务 ID 不匹配、缺少产物信息不猜测成功；终态冲突需显式核对。网络恢复不重置耗尽预算，局部故障不阻断可独立处理的本地操作。 |
| 版本及连接身份不兼容 | 接入握手检查兼容性，拒绝不兼容连接；不隐式执行破坏性数据迁移，不用新账号或端点盲目操作旧任务。 |

### 非目标

- macOS、Linux、WSL、容器、跨机器调度、跨操作系统用户共享及多租户权限。
- 多供应商路由、自动切换、多账号并行配置、任意 HTTP 请求透传。
- 批次事务、自动任务依赖、人工插队、用户可控全局暂停、本地视频剪辑转码或内容质量自动验收；已明确纳入的模型原生 edit/extend、样片转成片及独立超分不在此排除项中。
- 任务／生成视频删除 tools、自动视频清理、云同步、UNC 路径交付、内置播放器、视频流服务。
- 运行环境配置热更新（不包括可即时更新的优化授权偏好）、旧任务目录自动迁移、Windows 系统代理或 PAC 自动发现、代理池、任意版本自动迁移。
- 任意 Host 兼容承诺、性能 SLA 或长时间压力认证。

## Capabilities

### New Capabilities

- `shared-local-runtime`: Windows stdio 接入、共享后端唯一性、连接生命周期、健康状态及版本兼容。
- `provider-api-contracts`: 固定 26 模型矩阵、独立超分 tool 契约、预检、参数规则、连接身份及响应分类。
- `task-admission`: 有界接收、持久化幂等、有效参数与优化授权固定、请求找回及素材接收一致性。
- `task-scheduling-recovery`: 全局额度、可派发 FIFO、自动推进、故障保护、重启恢复及版本化任务管理。
- `input-material-lifecycle`: 托管素材、上游临时上传、完整性修复、终态清理及清理恢复。
- `video-artifact-delivery`: 多产物下载、完整性状态、持久化、恢复及受控路径复制。
- `agent-task-observability`: 分页查询、异常名单、有界等待、实扣费用、精简错误及脱敏诊断。
- `runtime-configuration`: 统一配置、可撤销共享优化授权、冲突处理、目录固定、代理及可信证书策略。

### Modified Capabilities

本 change 不修改既有业务能力。以上八项能力对应 change 内的 delta specs；后续已导入 manual-writing、git-collaboration、engineering-practices 工作规范，八项业务主规范尚未同步。

## Impact

### 现有能力与技术约束

规划起点时仓库只有 OpenSpec 配置、工作约定及辅助文件，没有业务实现、依赖清单或测试可直接复用。本次将新增服务、持久化与调度能力、供应商适配、工具契约、安装配置文档及验证体系；复用现有 OpenSpec 流程，不默认引入其他项目代码。

已选技术栈为 uv 管理的 Python **3.12.14**、**MCP SDK v2** 和异步 HTTP 库 **httpx2**。发行来源和候选版本元数据已在 design 阶段核实，当前 Windows 安装和隔离运行已有验证记录；13.1 干净 Windows Sandbox 安装和13.3 实际 Host 跨 Host 主视频交付已按任务完成判断验收，范围及限制见当前验证记录，不擅自换成其他库。Windows 后端协调、进程间通信、存储引擎及具体工具名称见 design。

### 契约依据与待核实项

依据用户在本次对话逐批提供并确认的 26 个模型页面、超分契约及优化授权规则整理；通用参考为 [供应商 llms 文档](https://api.seedance.nz/docs/llms.txt)。用户明确选用兼容端点，具体模型约束优先于通用模板，示例值不自动视为默认值；global 表示区域身份，不构成审核通过保证。以下是文档层面契约，并非真实调用验证结果。

### 默认发行执行保护补充（2026-11-14）

默认入口已规划接通已核实适配器，安装配置EXECUTION_MODE默认local，显式provider并重启后新正式提交才执行。接收事务持久化执行授权，旧/local任务不自动获权；保持原任务、占位及未知结果，不能因升级意外派发。此为安装级启用控制，不新增Agent全局暂停工具或每任务二次确认。详见design发行入口补充与14.1任务；实际Host和干净Windows验收仍独立。

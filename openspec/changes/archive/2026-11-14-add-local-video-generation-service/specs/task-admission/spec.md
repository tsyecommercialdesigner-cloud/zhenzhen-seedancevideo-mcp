# Spec Delta

## Purpose

保证 Agent 的正式生成请求在多个 Host 并发和服务重启后仍被可靠且最多一次接收，明确预检与授权、输入固定、容量拒绝及接收中状态，避免响应丢失引起重复生成任务。

## ADDED Requirements

### Requirement: 独立任务与提交授权

系统 SHALL 要求每次正式提交指定一个 api_id、一组参数及 request_key，创建独立任务；接收即允许后台自动执行，无二次确认，不内部拆成多个生成任务。

#### Scenario: 直接提交
- **WHEN** Agent 未预检但正式请求有效且提示词优化符合独立授权规则
- **THEN** 完成接收后自动排队推进；不要求预检令牌，不等待再次授权。

#### Scenario: 有意重新生成
- **WHEN** Agent 用新 request_key 提交相同内容并关联原任务
- **THEN** 创建新的独立任务；不把其误判为重复请求，不引入批次事务或依赖。

### Requirement: 持久化幂等与找回

系统 SHALL 在共享后端范围持久化 request_key 与规范化请求的对应关系；同标识同请求返回原任务，不同内容报冲突，并提供按标识只读找回。

#### Scenario: 跨 Host 同时提交
- **WHEN** 两个 Host 提交相同标识和请求
- **THEN** 最多接收一个任务、占用一个名额并返回同一任务 ID；接收中不得启动第二份素材托管。

#### Scenario: 内容冲突
- **WHEN** 同标识的 API、模型、任务类型、有效生成参数或本地素材内容摘要不同
- **THEN** 明确报冲突，不覆盖原任务；不能仅以路径相同认定素材相同。

#### Scenario: 响应丢失后重试
- **WHEN** 已接收任务的响应丢失或后端已重启
- **THEN** 按原标识返回原任务；即使队列满也不拒绝已有任务找回，即使原素材已删除也可只读找回。

### Requirement: 有界且完整的任务接收

系统 SHALL 配置等待队列容量与单任务输入大小限制，仅必要素材已托管且任务持久化后确认入队；失败不得永久占用标识或容量。

#### Scenario: 容量或素材超限
- **WHEN** 新的有效请求超出接收上限
- **THEN** 明确拒绝，不挤掉已有任务、不确认入队，并允许原标识稍后重试。

#### Scenario: 接收中或中断
- **WHEN** 素材仍在托管、复制失败或接收阶段崩溃
- **THEN** 有界响应接收中或未接收，不冒充入队；恢复核对已提交记录，清理未完成接收的临时副本及容量预留。

#### Scenario: 正式检查变化
- **WHEN** 预检后文件消失或 API 进入拒绝接收的故障保护
- **THEN** 正式提交按当前条件明确拒绝，不绕过校验。

### Requirement: 请求规范化及默认值固定

系统 SHALL 接收时固定服务声明的有效参数与参数规则版本；规范化不改变生成意图，不忽略未知字段，不随升级重解释旧任务。

#### Scenario: 默认值变化
- **WHEN** 服务升级修改默认值后执行旧排队任务或重放原请求
- **THEN** 旧任务沿用原有效参数，幂等比较按原规则；新默认仅影响新任务。

#### Scenario: 上游隐式默认
- **WHEN** 某默认行为由上游隐式决定且不可核实
- **THEN** 明确其不确定性，不宣称结果可复现；URL 按引用比较，不擅自移除签名参数。

#### Scenario: 旧参数不再支持
- **WHEN** 上游不再接受已接收任务的参数
- **THEN** 标记需要处理，不自动换模型、删参数或切换 API。

### Requirement: 调用中断不撤销接收

系统 SHALL 不将工具超时或取消等待解释为撤销已接收任务的执行授权。

#### Scenario: 提交调用被取消
- **WHEN** 调用结束但任务可能已接收
- **THEN** 接收流程最终可靠完成或清理失败接收；Agent 按标识找回，取消已接收任务必须使用任务取消操作。


### Requirement: 提示词优化显式授权

系统 SHALL 对可优化提示词的常规模型采用顶层 enhance_prompt，初始有效默认 false；Agent 可在正式提交前询问单次允许或总是允许，无明确授权不启用，单次显式 false 优先。

#### Scenario: 未授权默认关闭
- **WHEN** 未设置总是允许且当前请求无单次用户允许
- **THEN** 预检和提交显示有效 enhance_prompt=false；请求 true 但无法确认授权时拒绝开启并提示提交前授权，不让已入队任务等待交互。

#### Scenario: 单次允许
- **WHEN** 用户明确允许当前任务优化
- **THEN** 当前任务有效 true，记录单次授权来源，不开启跨任务偏好；使用新 request_key 重新生成需要独立有效授权。

#### Scenario: 共享允许与单次关闭
- **WHEN** 共享总是允许有效但当前请求显式 false
- **THEN** 当前任务按 false 固定，不撤销共享偏好；省略且无单次关闭时可依据共享授权采用 true。

#### Scenario: 不适用能力
- **WHEN** 调用成片或超分 tool
- **THEN** 有效优化状态为不适用，不发送 enhance_prompt；即使共享偏好开启也不优化，显式请求 true 则报不适用，不静默忽略。

### Requirement: 授权快照参与幂等

系统 SHALL 接收时持久化有效 enhance_prompt、适用性及授权来源，并纳入有效请求身份；重试、重启和偏好撤销不重算已接收请求。

#### Scenario: 撤销后找回
- **WHEN** 原任务已按总是允许接收，之后偏好撤销再重放同一请求
- **THEN** 返回原任务及原授权快照；不能因当前偏好不同判为新任务，也不重新发送生成请求。

#### Scenario: 修改已接收请求
- **WHEN** 同 request_key 将原有效优化值改成相反值
- **THEN** 报内容冲突，不修改已接收任务；用户如需停止原任务按取消或放弃契约处理。

### Requirement: 派生任务仍需独立提交

系统 SHALL 将样片、成片和独立超分分别作为新的显式任务接收，固定被引用的供应商样片 ID 或输入素材身份，不建立自动付费任务链。

#### Scenario: 样片成功后
- **WHEN** 样片已就绪且具备成片条件
- **THEN** 仅提供可用动作，不自动发起成片；显式成片请求使用新 request_key 并记录关联。

#### Scenario: 生成后超分
- **WHEN** 用户要求对已有产物超分
- **THEN** 新请求独立去重、占队列容量；不修改原任务或把其重试解释为超分。

### 本地样片事实接线补充（2026-11-14）

1.6复核发现DraftFact校验尚未由正式工具接入任务库。预检只读查找同connection_binding下唯一匹配的remote_id；正式接收事务重新读取，真实适配器派发前再核对。仅据本地模型区域、已固定draft参数和已记录生成状态拒绝已知不符，不把相同连接绑定当作账号证明，不从created_at猜7天起算。外部ID、不同连接绑定或多条匹配均保持来源/账号/有效期待核实，不选择任意一条。相比让Agent传已验证标志或额外请求供应商身份接口，本方案仅复用受保护本地事实，不增加上游调用或schema迁移。重复request_key先返回原任务，不因后来状态变化重新接收；派发前发现已知不符转待处理，不自动补做样片。

## Context

本设计对应 `add-local-video-generation-service`，动机见 proposal 的 Why，行为约束见本 change 的八份 specs。规划起点时仓库尚无业务代码、依赖锁或运行验证；当前状态见文首。本文件确定实现方案，不代表已实现、已接入供应商或已完成真实验收。

运行环境限定 Windows、uv 管理的 Python 3.12.14、MCP SDK v2、httpx2。用户已确认 26 个 Seedance 模型、独立超分、兼容端点、临时素材上传和提示词优化授权；完整兼容端点响应仍有缺口。设计把这些缺口限制在版本化供应商适配器中，不以猜测填补。

## Goals / Non-Goals

**Goals:**

- 将 Host 连接寿命、任务执行授权、远端结果、文件交付分别建模，使跨 Host 和跨重启操作具有一致含义。
- 以单一持久化写入点和先落账后执行的操作记录，控制并发竞争与崩溃后的副作用；明确不能保证上游 exactly-once。
- 将模型参数、授权、配置和输入身份冻结为可解释快照，使适配器升级不会重新解释旧任务。
- 使用可安装的单个 Python 包，不要求用户部署额外数据库或消息服务。

**Non-Goals:**

- 不实现跨用户或跨机器服务，不引入 Web 管理端、远程 HTTP MCP 服务、Redis、Celery 或 Windows 常驻系统服务。
- 不把本地业务任务绑定到 Host 是否支持 MCP 协议的 Tasks 扩展，也不依赖推送或 MCP elicitation 完成提交授权。
- 不实现供应商未证明的取消、历史反查、上传删除、费用预扣调用或下载续传；不引入自动成片／超分任务链。

## Decisions

### 1. 包、依赖与模块边界

采用 `src` 布局的单一发行包，入口暂定 `zhenzhen-seedance-video`，默认启动 stdio 前端，内部子命令 `backend` 启动共享后端。模块按职责分为 MCP 工具、内部 RPC、Windows 运行协调、配置、任务服务、存储、调度、供应商适配、素材、产物与诊断。工具层只负责协议转换，不能直接操作供应商或任务库。

`.python-version` 锁定 3.12.14，项目 Python 范围限定 `==3.12.14`，使用 uv 生成并提交 `uv.lock`；安装和运行使用冻结锁文件。2026-11-12 查询 [mcp 发行元数据](https://pypi.org/pypi/mcp/json) 得到 2.3.0、依赖 httpx2>=2.10.0 和 mcp-types==2.3.0；[httpx2 发行元数据](https://pypi.org/pypi/httpx2/json) 得到 2.16.0、Python>=3.11。以 mcp==2.3.0、httpx2==2.16.0 作为首次锁定候选，元数据允许 Python 3.12；实际 uv 解析、Windows 安装及异步行为尚未验证，失败时先说明原因，不擅自改为 httpx 或 SDK v1。

前端按 [SDK v2 迁移资料](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/whats-new.md) 使用 v2 服务接口，不复制 v1 FastMCP 示例。Windows 安全对象操作显式依赖 pywin32；配置解析使用 python-dotenv，但禁用变量插值和隐式 cwd 搜索。其余以标准库 asyncio、sqlite3、ssl、hashlib、decimal 为主。候选依赖仅在后续实施锁定，本轮不安装。

备选为多个独立服务包及外部队列，部署、版本协调与退出恢复成本更高；当前规模采用单包与清晰模块边界即可。

### 2. stdio 前端与每用户唯一后端

每个 Host 启动自己的前端；stdout 仅用于 MCP，诊断写脱敏 stderr。前端连接后端，转发有界请求并持有租约，不持有调度状态。后端由前端按需创建，运行独立于任一前端的进程生命周期。

内部通信选择绑定 `127.0.0.1` 随机端口的 asyncio TCP 长连接，采用长度前缀 JSON 帧、请求 ID 和协议版本；不是对外 HTTP API。运行目录受当前 Windows SID 的 ACL 保护，发现文件包含 PID、进程创建时间、实例随机标识、端口及协议版本，独立凭据文件保存随机 256 位连接令牌。鉴权成功前不处理业务帧，也不计为 Host；限制帧大小、认证时限、连接数和单连接在途数。令牌不进入命令行、MCP 响应或日志。它只阻止其他用户随意接入，不对同用户恶意进程承诺隔离。

选择回环 TCP 是为了使用标准异步流、便于模拟客户端和 Host 验证；备选 Windows 命名管道可用 SID ACL，但异步管道封装及取消处理增加维护成本。不能因 TCP 接入失败退回无鉴权端口或公开网卡。

唯一性采用用户数据目录内两个稳定锁文件的 Win32 独占句柄：短期启动锁串行化发现／拉起，后端持有所有权锁直到退出。锁文件不删除再创建，不以时间戳判断失效。后端取得所有权锁并核对旧实例退出后，才打开任务库恢复调度；前端不能打开第二份库逃避冲突。

接管同时需要所有权锁可取得及旧实例身份核对。使用 PID 和创建时间识别原进程，获取进程句柄并确认退出；PID 已复用不当成原实例。原进程仍活着、访问被拒、启动状态不确定或锁仍占用，都有界等待后明确失败，不强杀。发现文件只作定位线索，不作所有权证明。首次启动无历史记录可建立新库；存在历史数据而库缺失／损坏时禁止自动初始化空库。

拉起使用当前受 uv 管理环境的解释器、固定模块入口、绝对工作目录和隐藏窗口标志，避免 shell 拼接。需验证 Windows Job Object 对子进程的限制；若 Host 的作业不允许后端独立存活且不能合法脱离，返回不兼容诊断，不假装具备跨 Host 保活能力。无须管理员权限，不安装服务。

Windows 隔离验证补充：虚拟环境启动器可能再创建实际解释器进程，不能将 CreateProcess 返回的启动器 PID 直接当作后端 PID。拉起先挂起启动器，可靠保存 starting.json 的启动器身份和随机启动标识，再恢复执行；实际后端在 discovery.json 保存自身 PID／创建时间及同一启动标识。该标识仅关联启动，不替代旧实例退出核验或所有权锁。Job Object 验证针对具体 Host Job 的归属和该 Job 关闭后的存活，不要求后台完全不属于任何 Python 启动器 Job。

前端在 stdio EOF、Host 退出或协议关闭时断开租约；有心跳用于回收半开连接。最后一个有效连接消失立即关闭新生成派发门，宽限期已有查询／下载可继续；重连取消退出。宽限期结束进入 draining，不再启动新网络操作，有限收尾后退出；此阶段新连接收到稍后重连，不重新打开已关闭的调度器。前端只能确认旧进程退出后重新拉起。

### 3. SQLite 作为持久化事实源

后端是唯一数据库拥有者。使用 sqlite3、WAL、foreign_keys=ON、synchronous=FULL 和有界 busy timeout；专用单线程执行数据库操作，asyncio 通过队列等待，避免文件 I/O 阻塞事件循环。文件复制、摘要与删除使用有界工作线程。数据库和锁放本地固定用户目录，不放网络盘或由视频输出配置移动。

核心记录如下，字段为设计职责，不要求此时生成完整 DDL：

| 记录 | 内容与不变量 |
| --- | --- |
| tasks | 本地 UUID、唯一 request_key、api_id/model/kind、规范化版本、原始意图摘要与有效参数、入队序号、输出目录、连接身份、状态版本 |
| admissions | 接收预留、素材暂存、拥有操作、大小预算；成功原子转换为 task，失败可释放重试 |
| attempts | 阶段、轮次、操作 epoch、intent/finished、请求起止、剩余预算、next_attempt_at、可靠远端 ID 与证据摘要 |
| remote_observations | 有界结构化事实与出处、原状态、远端 ID、终态冲突；不存整份原始响应 |
| material_copies / uploads | 所有权、稳定摘要、大小、托管路径；临时 URL 与到期信息独立于输入身份 |
| artifacts | 产物身份、来源、必需性、固定目标、临时路径、摘要、发布与登记状态 |
| cleanup_jobs | 清理依据、登记路径、预算、执行结果，不能由任意外部路径构造 |
| preferences | 用户级优化授权、授权版本、来源与撤销时间 |
| task_events / diagnostics | 业务变更和脱敏故障索引，版本化动作证据与待处理原因 |

金额用 Decimal 解码并存十进制文本及原币种，避免二进制浮点误差；费用为最新已确认实际值，不累加每次响应。缺金额或币种则保存未完整返回状态。

SQLite 适合单机单写者的事务和去重，优于散落 JSON 文件；外部数据库会增加用户部署和恢复负担。WAL 不解决数据库与供应商／文件系统的跨系统原子性，因此必须有操作意图和恢复核对。

任何新副作用前先提交 intent。数据库错误使后端进入 storage_fault，关闭接收、新提交、下载和清理门；在途操作有限收尾，不能只用内存事实释放额度。恢复先确认库可写及未决记录一致再开放调度；不自动重建库。只读结果注明最近可靠状态及可能滞后。

### 4. 状态采用正交字段与持久化占位

不使用一个 success/failed 字段覆盖所有情况。任务保留以下维度：

- 接收／阶段：receiving、queued、preparing、submitting、tracking、downloading、settled。
- 远端事实：not_submitted、unknown、queued、running、succeeded、failed、cancelled，含原值、出处和时间。
- 自动执行模式：active、needs_attention、abandoned；另存取消意图。
- 本地产物：none、pending、partial、ready、missing、changed；清理独立状态。
- 待处理原因集合、generation_slot_held、跟踪轮次、业务 version 与操作 epoch。

本地取消与远端取消分开，不将提交前取消写为上游已取消。未知查询可保留最后 running 事实，同时以当前可信度／待处理原因表达状态未知。远端成功不等于文件 ready；清理失败不改变生成结果。

每个任务变更在事务中串行，管理动作带 expected_version；过期返回 VERSION_CONFLICT 和最新摘要。已达到目标状态的重复动作返回无操作，不新建预算或网络工作；不同意图不能被此规则吞掉。用户可见 version 仅因业务事实／动作变化增加，查询时间单独更新。

异步操作携带 epoch。取消、放弃等控制改变 epoch，旧操作返回时允许关联并保存可靠事实，但不能恢复自动执行或重新占位。显式 refresh 是新授权操作，确认成功可开启下载；它与旧的迟到查询严格区分。

占位在派发事务中取得，成功／明确失败／明确取消／显式放弃后在事务中释放；未知、跟踪超时仍保留。generation_slot_held 的数据库记录是权威，启动求和重建内存计数，不仅依赖 asyncio.Semaphore。放弃后的 running 任务恢复须原子重新取得额度；仅刷新不占生成额度。

### 5. 接收、去重及授权快照

正式提交顺序为：识别 request_key → 读取已有记录或原子创建接收预留 → 校验模型和授权 → 预留队列及素材容量 → 复制本地素材并计算 SHA-256 → 持久化任务与素材登记 → 返回 accepted。接收没有调用付费生成。若调用等待已结束，接收操作仍在后端完成或回滚；Agent 用 request_key 找回，不能将 receiving 视为已入队。

相同 request_key 的并发调用复用一个接收过程，不开始第二组复制。正式 task 以唯一约束兜底。失败预留及孤立临时文件恢复清理，不永久占用标识；接收结果不明优先查已提交事务，不能直接重做。

规范化保留字段缺省与 false 的区别、素材顺序和 URL 签名，使用本地内容摘要而非路径作为身份；供应商临时上传 URL 不参与请求身份。记录契约版本、调用方明确参数与已解析快照，以原规则比较重放。历史重放不会因现在的默认值或优化偏好变化而冲突；明确修改模型、有效参数或素材则冲突。原素材不可读时可按 request_key 只读取回，但不能宣称已验证一次带素材的重提完全相同。

提示词优化决策与任务接收处于同一授权版本视图：适用请求显式 false 最高优先级；否则单次用户允许或已持久化总是允许可得到 true；未授权默认 false。请求 true 无授权依据报 AUTHORIZATION_REQUIRED，不把请求放进等待用户交互的队列。

工具传单次授权声明及来源，或通过独立偏好操作保存总是允许／撤销。MCP Server 信任同用户 Agent 对用户决定的声明，不声称技术上证明人类点击；Host 应先询问用户。单次声明仅绑定当前 request_key，新标识不能自动复用。偏好写入和接收按事务顺序决定生效边界，已接受任务不被后来撤销改写。成片／超分不适用优化，拒绝 true 并不向上游发送该字段。

### 6. 调度、重试和恢复算法

调度器按单调入队序号选择最早可派发任务，跳过受 API 保护、素材需修复或连接身份不兼容任务；保留原序号及等待队列容量。前置准备采用有限并发，准备完成后仍按可派发顺序争取生成额度，不能因上传先结束而任意插队。

生成请求发送前事务同时写入占位、提交 intent、attempt ID 和跟踪开始时间。此后网络异常，即使看起来像超时，也不能假定未发送。仅适配器提供可靠未接单证据才走可显式重试分支；不向上游虚构 request_key 幂等头。

普通 queued/in_progress 轮询属于进度跟踪，不消耗错误重试预算；连续暂时查询失败消耗预算，成功查询可结束这段连续失败并记录历史，已耗尽后不会因重启自行恢复。上传、下载和清理分别有阶段预算。配置／权限／磁盘错误直接待处理，不浪费暂时故障重试。退避记录 next_attempt_at，采用指数退避与抖动，已核实 Retry-After 在有界期限内使用；等待退避不占网络并发槽。

| 崩溃或退出时持久化阶段 | 下次启动的动作 |
| --- | --- |
| 接收未完成 | 核对最终 task 是否已提交；否则释放预留，清理登记临时副本 |
| 排队／素材准备，尚无提交 intent | 保留顺序与输入；恢复剩余上传预算，已知过期临时 URL 可重传同副本 |
| intent 存在、生成结果未落账 | 转提交结果不明，保留占位，绝不自动 POST |
| 已保存远端 ID，正常跟踪 | 身份兼容且预算／期限有效才恢复查询 |
| needs_attention／abandoned | 保持原控制状态，不自动恢复 |
| 已成功、下载未完 | 核对临时／已发布文件，仅恢复未完成部分和剩余预算 |
| 清理执行中 | 根据登记文件存在性核对，已不存在可补记完成 |

开始提交后记录 UTC 绝对跟踪期限，停机也消耗期限；进程内使用单调时钟控制等待，发现墙钟明显回拨时报告诊断，不以回拨无限延长预算。明确恢复自动跟踪创建新轮次、预算和期限，保留历史。工具等待取消只撤销 waiter；在途管理操作有限收尾，不撤销已提交事务。

正常关闭先禁止新网络操作、等待在途工作到收尾上限，再取消 I/O 并落账可保存事实。仍可能在上游执行的 POST 按未知处理；退出不能承诺上游已终止。数据库事务保持短小，不跨网络 await 持锁。

### 7. 供应商适配器与模型注册表

本地 api_id 固定为 `seedance-video` 和 `zhenzhen-upscaler`。前者使用 specs 中精确的 26 模型白名单，后者只允许 zhenzhen-upscaler；工具和端点数量不由模型数量决定。共享鉴权错误同时保护两个 API，已核实的模型级错误只阻挡对应模型；未知错误采用保守影响范围并返回原因。

适配器分为版本化注册表、参数校验／构造器、上传、提交、查询和响应解释器。输出统一 SubmissionEvidence、RemoteObservation、ArtifactReference、ActualCharge 和 ProviderError；其中“未接单证明”是明确证据类型，不能仅由 HTTP 4xx 构造。

注册表覆盖以下差异，完整枚举以 provider-api-contracts spec 为准：

| 契约族 | 构造与校验重点 |
| --- | --- |
| 2.0 常规 18 模型 | t2v 无媒体、i2v 1–2 帧、multi 9/3/3；Standard 才有 native 档；固定 4–15 秒为待核实暂定解释 |
| 2.5 常规 6 模型 | 4–30 秒、无 native4k、i2v 仅 adaptive；multi 30/10/10 且音视频时长限制；edit/extend 条件校验 |
| 2.5 draft 模式 | 有效分辨率显式改为 480p，接收摘要显示覆盖；保留原请求与有效参数 |
| 2 个 draft-to-video | 引用同账号同区域已完成样片、native1080p；省略 prompt、素材、seconds、enhance_prompt；省略尾帧选项保留继承含义 |
| 独立超分 | 一条 MP4 video_url，默认 1080p；不发占位 prompt／seconds，不调用未明 price-preview |

自动时长统一构造 metadata.duration=-1 并省略 seconds，明确固定时长与自动值冲突则拒绝。multi 仅接受 canonical content，不合并别名；不根据提示词内容猜测 edit。未列明的上游默认保留省略；本地明确默认 generate_audio=true、draft=false 及有效 enhance_prompt 则入快照。URL 内容时长无法本地确认时返回“未验证”，预检不能宣称供应商必然接受。

固定 Base URL https://api.seedance.nz，POST /v1/video/generations、GET /v1/video/generations/{id}，不自动探测切换 /v1/videos。SUCCESS/completed 映射 succeeded，failed 映射 failed；code=success 仅为封装结果。对任务 ID、状态和 URL 用已核实路径精确解析，禁止递归搜索任意 id/url/status。用户指定 id、metadata.url 的语义作为待完成映射，仍需完整兼容响应证明具体封装；data.usage 片段不充当完整成功 fixture。

终态冲突保存新观察和待处理原因，不直接覆盖原终态或删文件。未知／关联不一致响应不触发下载。费用可晚到，不为费用另开无限轮询。

不完整响应契约不阻止隔离开发，但阻止对应路径标为生产已验证；取消、身份反查、提交结果核对和链接刷新默认能力为待核实，工具返回 CAPABILITY_UNVERIFIED。不提供让 Agent 输入“已核实=true”即可绕过的后门。

### 8. 素材、上传与文件交付

用户数据根固定 `%LOCALAPPDATA%\ZhenzhenSeedanceVideo`，下设 `state`、`runtime`、`materials`、`diagnostics` 和默认 `outputs`。托管文件以任务／素材 UUID 命名，不用供应商或用户文件名拼接路径。文件复制时以受控句柄读取，记录大小及摘要，检测源变化，不一致则接收失败。

本地副本在派发前经 POST /v1/files/upload、Bearer、multipart file 上传；上传与生成 intent 分开。上传失败不标记生成已提交。保存临时 URL、上传时间及实际返回过期信息，未知有效期不自行保证 24 小时；已知到期仅在尚未提交生成时允许重传原副本。外部 URL 只保存引用，不自动下载作缓存。

下载使用目标目录内专用临时文件，流式写入、检查非空／已知长度／容器基本结构、计算 SHA-256，再刷新文件缓冲并原子发布。基本完整性不等于视频可播放性和内容质量验收。供应商摘要存在且算法已核实才额外比对，不把 ETag 自动当 MD5。首期不承诺 Range 续传，恢复重新下载未完成部分。

发布前持久化产物 intent 与预期摘要、尺寸、最终路径；发布后登记 ready。若发布后落账失败，重启依据 intent 核对实际文件再补记，不误判用户同名文件为自己的产物；无法确认则待处理。仅全部已定义必需产物 ready 才触发输入清理。尾帧必需性未核实不能自行增加或忽略需求，能力查询明确待核实。

交付 copy_artifact 接收 artifact_id、target_path、可选 workspace_root 和 overwrite=false。相对目标要求显式本地绝对 workspace_root；校验规范化路径、现有父目录最终解析路径及重解析点，拒绝越界、UNC、驱动器相对路径和备用数据流。创建父目录后发布前重新校验，Windows 句柄／共享模式约束防止检查后目录被替换；不只用字符串 startswith 判断归属。

复制到目标同目录临时文件，核对源摘要和目标副本摘要；overwrite=false 使用不替换既有文件的原子发布，overwrite=true 才使用替换发布。任务原产物路径禁止作为覆盖目标；源目标相同返回明确无操作。发布失败保留原目标，发布成功响应丢失不回删目标。工作区副本不继续托管。

清理先持久化依据和待办，撤销仍读取素材的旧操作并等待文件句柄结束后，逐项删除已登记且确认归属的副本；不递归删除任意传入目录，不跟随重解析点。即便放弃时远端未知，也依用户确认清理本地副本；远端上传 URL 是否删除不在首期。生成原产物作为超分输入时另建托管副本，不能将原产物登记为可清理输入。

### 9. 配置、凭据与统一网络层

API 密钥唯一配置名为 **ZHENZHEN_SEEDANCE_API_KEY**。配置文件位于 MCP Server 实际安装目录 `<install_root>/.env`，不从 Host cwd、Agent 工作区、HOME 或用户数据根搜索。安装根须由服务安装布局或明确启动入口可靠定位；无法定位时明确拒绝，不能猜测目录。逐字段优先级为安装目录 `.env` > 当前进程环境 > Windows 当前运行用户级环境 > 声明的默认值。仅字段未定义才回退；文件存在但读取／解析失败、重复字段、空值或非法值均报错。Windows 用户级回退需显式读取当前账号设置，不能把进程继承当作实时注册表读取；高优先级已有值不会被低优先级覆盖。禁用插值，不将 API_KEY、SEEDANCE_API_KEY 当作别名。配置仍由后端固定，新接入方按解析后的显式配置检查冲突；升级保留安装目录的私有 .env，状态根不迁移。

安装根实现通过模块位置识别已知布局：源码／editable 使用项目名匹配的 src 所属项目根；wheel 在项目 .venv 内使用其父目录，独立虚拟环境则使用虚拟环境根，均核对 pyvenv.cfg。拒绝无法识别的全局安装；不选择 cwd 向上搜索或环境覆盖路径，避免 Host 工作目录改变配置来源。文件按 UTF-8（兼容 BOM）逐条解析检查重复及语法错误；用户环境只读 HKCU\Environment，字符串保持字面值。RPC 后端仅比较前端解析后的显式值，不重读自身配置覆盖来值。

其他配置使用 ZHENZHEN_SEEDANCE_ 前缀，视频目录名为 ZHENZHEN_SEEDANCE_OUTPUT_DIR。新 Host 仅比较它显式提供的值；未指定项采用已运行后端。前端传递配置来源与候选值到经鉴权内部通道，后端比较后仅返回冲突项名，密钥不回显、不返回摘要。首个后端固定快照，环境配置重启才生效；授权偏好是数据库业务状态，不走环境重载。

密钥仅在启动配置和进程内存中使用，不入任务、命令行或日志。用于跨启动识别凭据是否未变的内部指纹采用带随机秘密的 HMAC，秘密由 Windows DPAPI 当前用户保护并持久化；指纹不对 Agent 暴露，不作为账号身份证明。任务记录非敏感连接绑定 ID、端点及模型区域。相同凭据与端点可保持已有绑定；换钥后没有可靠账号核验依据，旧远端任务转待处理，不能把换钥自动认定同账号或新账号。同账号核验适配器将来核实后才接续；已有本地产物仍可交付。

统一 NetworkPolicy 管理 httpx2 异步客户端、连接池、请求超时、代理、绕过及 SSLContext。禁用 httpx2 自动读取环境代理；只接受显式服务配置，避免 Host 的 HTTP_PROXY/NO_PROXY 意外改变行为。默认系统可信根加证书验证，可附加用户 CA 文件；不能 verify=false。代理首期支持明确的 HTTP/HTTPS 代理 URL，绕过支持精确域名／域后缀／IP/CIDR，不支持 PAC 或隐式系统代理。

供应商鉴权客户端与无凭据产物客户端下载逻辑分离，不将 Bearer 设置为所有请求的默认头。重定向逐跳有界处理并重新选代理、验证目标；不跨 origin 转发 API 凭据，不允许 HTTPS 降级 HTTP。下载是否需要认证依已核实契约决定，不能为解决 403 盲目附加密钥。内网／回环／链路本地下载目标默认拒绝，代理仅连接用户显式配置地址；不访问由上游错误文本建议的新地址。

### 10. 首期运行默认值

以下是本地保守默认值，可由同名前缀配置覆盖，不代表供应商配额或 SLA。所有数值范围在启动时校验；大于零，只有 TRACKING_TIMEOUT_SECONDS=0 表示关闭跟踪期限。资源限制降低不取消已存在任务。

| 配置后缀／策略 | 默认值 | 说明 |
| --- | --- | --- |
| GENERATION_CONCURRENCY / QUERY_CONCURRENCY / DOWNLOAD_CONCURRENCY | 3 / 4 / 2 | 生成占位与网络 I/O 额度分离 |
| UPLOAD_CONCURRENCY / ADMISSION_CONCURRENCY / CLEANUP_CONCURRENCY | 2 / 2 / 1 | 避免大量文件操作占满机器 |
| QUEUE_LIMIT / INPUT_BYTES_LIMIT | 100 / 536870912 | 等待及接收预留计入队列；每任务本地输入总计 512 MiB，不覆盖更小模型限制 |
| CONNECT_TIMEOUT_SECONDS / REQUEST_TIMEOUT_SECONDS | 10 / 60 | 提交、查询包含总请求期限，连接超时是其子限制 |
| UPLOAD_TIMEOUT_SECONDS / DOWNLOAD_TIMEOUT_SECONDS | 300 / 1800 | 单次总期限；流式读取空闲上限 60 秒 |
| TRACKING_TIMEOUT_SECONDS / POLL_INTERVAL_SECONDS | 21600 / 5 | 跟踪默认 6 小时；轮询含抖动，限流可延后 |
| QUERY_RETRIES / UPLOAD_RETRIES / DOWNLOAD_RETRIES / CLEANUP_RETRIES | 5 / 3 / 3 / 3 | 指首次失败之后最多额外重试次数，预算持久化；生成 POST 自动重试为 0 |

| SHUTDOWN_GRACE_SECONDS / SHUTDOWN_DRAIN_SECONDS | 10 / 15 | 无 Host 的宽限及有限收尾分开计时 |
| 租约心跳／失效 / STARTUP_TIMEOUT_SECONDS | 5 / 20 / 30 秒 | 启动失败明确返回；不因超时自行判定旧后端退出 |
| 工具默认等待／最大等待 | 20 / 30 秒 | 等待结束后任务继续，按 request_key 或 task_id 找回 |
| 列表默认／最大页大小 | 20 / 100 | 能力详情亦按模型请求，避免一次输出全部 schema |

下载产物大小不由输入限额推导；支持独立可配置下载字节上限，默认不额外限制，仍受磁盘余量和总期限约束。上游 JSON 响应和内部 RPC 帧设独立硬上限（分别 2 MiB、8 MiB），超限作为协议／输入错误，不将大内容转入 Agent 上下文。诊断日志轮转，仅保留脱敏事件，默认每文件 10 MiB、5 份；这不清除任务或视频。

### 11. MCP 工具与可观察性

工具暂定以下名称，统一以本地 task_id 操作，远端 ID 只作事实字段。所有变更工具提供结构化结果，任务级变更使用 expected_version；不会按工具名执行任意远端 HTTP。安全只读标注仅用于真正无变更操作，refresh 会访问上游并可能触发已授权下载，不能标注为只读。

| 工具 | 核心职责 |
| --- | --- |
| get_service_status / get_capabilities | 本地与上游分层健康、额度、按 api_id/model 的能力和待核实信息 |
| preflight_video_task | 按 task_kind 校验生成／超分参数、素材和优化决定，无上传或生成副作用 |
| submit_video / upscale_video | 独立提交入口，均需 request_key；超分不接受生成专用参数 |
| get_task / find_task_by_request_key / list_tasks | 本地查询；list 支持待处理原因和状态不明筛选 |
| wait_task | after_version + 有界 timeout，不访问上游 |
| refresh_task / resume_task_tracking | 单次刷新与新轮次自动跟踪分离，同任务在途等价查询合并 |
| cancel_task / abandon_task | 版本化控制；放弃需原因及 acknowledge_remote_may_continue=true |
| retry_unsubmitted_task | 仅有可靠未创建证据时显式重试原任务，不能用调用方声明替代证据 |
| repair_task_materials / retry_material_cleanup | 补回同摘要素材／重试既有合法清理待办 |
| retry_task_download | 恢复未完成或显式确认异常产物，独立 overwrite=false |
| list_artifacts / verify_artifact / copy_artifact | 精简产物清单、显式完整性核验、受控交付 |
| get_prompt_optimization_policy / set_prompt_optimization_policy | 查询、设置总是允许及撤销，更新需当前 policy_version 与明确用户授权来源 |
| get_diagnostic | 只返回有界脱敏细节，不输出完整原始日志 |

未知终态核对能力未核实，首期不得增加可任意改写远端状态的工具；已声明的条件分支通过能力信息明确不可用，取得契约后仍走统一版本化状态服务。

响应包含 ok、task_id、version、stage、remote、delivery、attention、allowed_actions 和必要错误。长提示词／参数仅显式请求详情才返回，仍受界限；费用、授权来源、有效分辨率可直接给摘要。错误先按字段白名单构造，再脱敏和截断，不先截断再脱敏。未知异常使用内部诊断 ID，原始 traceback 不返回 Agent。

列表用不可变入队序号和 ID 作游标，游标绑定筛选参数；不承诺跨页快照。待处理记录非消费式，远端未知和下载异常分类可独立消退。wait 在同一任务锁内检查版本和登记 waiter，提交变化后再通知；通知丢失也可由超时前复查补偿。

### 12. 验证与交付证据

后续实施采用 pytest 的状态／事务测试和本地 HTTP 假服务：校验真实字节边界、超时、重定向及下载中断，不只 mock 适配器返回值。已核实供应商 fixtures 保留脱敏来源；合成 fixture 明确标为模拟，不据其宣称协议已核实。

验证层次分别记录：

1. 模型矩阵、优化授权优先级／撤销／重放、未知响应和费用的隔离测试；26 模型逐项声明覆盖，超分单独覆盖。
2. SQLite 和文件操作故障注入：提交前后、收到 ID 未落账、文件发布未登记、清理已删未落账；验证不重复 POST、不提前清理、不损伤已有文件。
3. Windows 多进程真实锁和 RPC：同时拉起、PID 复用／存活无响应、Host 强杀、宽限期重连、Job Object、版本和配置冲突；用独立临时用户数据根隔离生产状态。
4. uv 冻结安装与 stdio 客户端工具发现、实际 Host 接入分别验证，后者不能由前者替代。
5. 对正式接入 API 进行最小付费闭环及参数差异验收，成片和独立超分分别有证据；样本、调用次数和费用范围另行确定。未实测模型明确标记未验证，不将共享端点一次成功扩张为全部模型通过。

上述为 design 审阅阶段的验证计划；其后 tasks 已审阅并进入实施。当前分层证据与未验证项见 docs/delivery-evidence.md，不将本地隔离测试视为真实 Host 或供应商验收。

## Risks / Trade-offs

- [上游已接单但本地无 ID] → intent 保留占位并待处理；没有幂等／历史核验时无法自动找回，这是跨系统提交的明确限制。
- [共享后端被单个 Host 的 Windows 作业强制终止] → 验证脱离策略；不兼容时明确诊断，任务仍按持久化阶段恢复，不以提高权限绕过。
- [同用户进程可读配置或调用管理工具] → 符合同用户共享边界；ACL、令牌及脱敏防止无意暴露，不宣称项目或同用户恶意程序隔离。
- [SQLite 与文件发布不能同事务] → 双阶段发布记录、摘要核对与恢复补登记；不自动认领归属不明文件。
- [临时输入／产物 URL 过期] → 本地输入可在未提交时重传，产物仅用已核实刷新能力；不保证永久恢复。
- [释放本地占位后远端仍运行] → 放弃时明确提示可能继续计费及远端实际并发超限；不能将本地额度宣传为供应商全账号硬上限。
- [用户改时钟、磁盘不足或外部改文件] → 独立诊断、保守期限、存储保护及显式恢复，避免自动覆盖与静默改址。
- [请求 schema 与上游文档有缺口] → 隔离注册表和严格解码；待核实能力不宣称生产支持，真实闭环前补足关键响应证据。
- [固定 Python 补丁和依赖候选随时间变旧] → 尊重本次锁定，后续升级单独审阅并验证；元数据可兼容不等于运行已验证。

## Migration Plan

这是首个实现，没有既有业务数据迁移。后续先交付包、冻结锁和配置示例，示例仅使用 ZHENZHEN_SEEDANCE_API_KEY 占位；首次运行安全创建用户目录和初始 schema。安装目录与用户状态／输出目录分开，升级不删除后两者。

启动握手校验内部协议版本、后端版本和数据库 schema_version。升级前让全部 Host 正常退出并确认后端结束；如需数据迁移，使用显式离线流程及 SQLite 一致备份，验证成功才切换。普通启动不执行破坏性迁移；版本过新拒绝调度。

回滚只允许旧程序明确支持的数据库版本；否则停止并恢复受验证备份。备份后可能已提交的远端任务不能因恢复旧备份重新派发：保留迁移／回滚操作记录，核对该时间窗口的提交意图和远端事实，未完成核对前禁止自动派发。不能将“恢复数据库文件”当作供应商副作用回滚。

### 接收实现细化（2026-11-13，第 7 组）

本地素材在原 URL 位置使用 `{ "local_path": "E:\\media\\source.png" }`，支持 images 元素及 canonical content 的嵌套 url；外部 URL 继续使用字符串。选择结构化入口而非猜测字符串是 URL 还是文件路径，可明确区分引用与托管，且不新增任意文件读取工具。仅接受本地绝对路径，不接收 UNC、驱动器相对路径、备用数据流或重解析路径。复制期间 Windows 只共享读取，拒绝并发写入／删除；前后核对身份和大小并流式计算 SHA-256。

admissions 在复制前登记随机托管文件名和预留；任务、material_copies、accepted 事件及删除预留在一个 SQLite 事务内提交。accepted 事件保存显式内容身份、有效内容身份、规则版本、授权来源和偏好版本，无需新增 schema 或隐式迁移。task.effective_parameters 中本地 URL 位保存 `{material_id: ...}`，未来上传适配器必须解析为上传 URL，不能直接透传该内部对象。外部签名 URL 原样保留在受保护任务库，不回显到接收摘要。

同 key 在同一后端合并接收；后续调用重新散列提供的本地素材，按内容而非原路径对比。原件消失时用只读 find_task_by_request_key，不重新提交。原显式身份完全相同时直接读取旧快照；等价显式默认值用旧有效值比较，不应用新的授权偏好。授权于接收提交事务内重新读取，单次关闭优先，单次允许声明仅属于该次请求，总是允许写入 preferences，失败不确认授权。

素材修复先记录 material_repair intent 并将素材置为 repairing；begin_submission 拒绝非 ready 素材。相同摘要／大小的临时副本才可原子替换托管文件，随后落账版本。中断或失败保留门控，允许显式重新补回；启动清理已登记修复临时文件，不从素材存在推断已完成修复，不自动重启生成。修复不修改任务参数、排队位置或取消／放弃状态。

### 网络与合成调度实现细化（2026-11-13，第 8–9 组）

统一网络层逐跳解析并校验全部目标地址，再固定公网 IP，保留原 Host 和 TLS SNI；相比仅检查 DNS 后让客户端重新解析，这避免 DNS 变更绕过私网限制。连接池按原 origin、代理和鉴权用途隔离，避免固定 IP 后不同 TLS 名称错误复用。HTTPS 代理单独配置同一 SSLContext；HTTP 代理不传 proxy_ssl_context（httpcore2 明确拒绝该组合）。无 Cookie 或跨域 Bearer 转发，非 GET 不自动跟随重定向。内部回环测试注入不进入用户配置或工具 schema。

调度器通过内部 adapter.prepare/submit/query 接口组装；production backend 尚无已核实完整适配器，保留 generation_execution=not_implemented，不自动调用真实供应商。合成自动 runner 验证 FIFO、提交 intent／占位、未知保留、轮询、刷新／恢复与有限关闭。prepare 的真实上传预算和 URL 生命周期仍属于未完成的 8.3。

查询预算复用 attempts，以 phase=query_budget、tracking_round、remaining_budget、next_attempt_at 记录；其 state=finished 表示预算记录不是未完成的付费请求 intent。query_failed/query_succeeded 事件记录每次结果和剩余预算，恢复新轮次不覆盖旧行。API／模型保护复用 preferences 的 dispatch 命名空间，与提示词优化偏好分离；解除须内部配置修复或已核实非付费检查依据。下载／清理阶段恢复尚待对应模块，不将只完成生成跟踪恢复算作完整 9.6。

### 产物文件实现细化（2026-11-13，第 10 组）

下载和复制沿用统一网络层与 SQLite 单写者。文件工作选择同目录独占临时文件、SHA-256 和 Windows 原子 rename；不采用跨卷移动或先截断目标。发布 intent 记录摘要、大小及临时文件的设备／文件身份，恢复要求最终文件身份及摘要一致，避免仅凭同名或同内容误认用户文件。目录逐级打开并禁止共享删除，锁住祖先直到发布结束；复制源禁止写入／删除共享，取消通过线程停止标记与等待句柄收尾协调。

容器检查仅验证 ISO BMFF 顶层 box 边界、ftyp 品牌、moov 和非空 mdat，区分 mp4 与 qt MOV；不承诺解码或内容质量。下载 URL、产物集合由内部已关联适配器提供，用户工具不接受任意 URL 下载。当前以合成适配器和本地 HTTP 假服务验证；未核实尾帧及链接刷新能力继续门控。


### 素材清理实现细化（第 11 组）

清理授权与任务事实在同一事务写入 cleanup_jobs；启动扫描仅补齐已满足条件且尚未登记的任务。new 待办首次认领时固定当前重试预算，删除前持久化 deleting 和已消耗次数；重启不重置。共享素材读取协调器阻止新读取、通知旧线程停止、取消异步上传并等待句柄释放；超时仍有读取则只记录忙碌，不执行删除。素材修复同样加入协调，避免放弃后修复操作重新创建副本。

删除只接受数据库 material_id，核对 root/material_id.input 与登记路径；Windows 目录句柄固定祖先，文件独占句柄核验大小和摘要后标记删除，关闭句柄完成删除。不采用目录递归删除或按任意工具路径删除。持久清理授权不因后来刷新／恢复而撤销，仍可凭远端 ID 找回产物；清理预算耗尽须显式版本化重试。上游取消触发条件只消费内部已确认事实，不新增未经核实的远端取消适配器。

### MCP 查询接线实施补充

查询层在同一数据库工作线程事务内组装快照、动作和摘要。wait_task 采用单调时钟期限及短间隔版本复查：相比进程内事件注册，复查无需为所有写入点新增通知协议，也不漏掉查询到等待之间的变更；代价是最多一个复查间隔的返回延迟。等待只比较业务 version，观察时间变化不触发返回。游标绑定筛选条件和不可变 sequence，以后端随机密钥签名；重启后旧游标明确失效，重新从首页开始。

统一工具门面复用已有接收、调度、产物和清理服务；生产适配器尚未核实的操作保持能力门控。合成适配器仅在测试构造时注入，不提供工具或环境变量切换后门。

内部 RPC 的调用取消只向 wait_task 和 copy_artifact 传播；接收与管理请求继续完成已授权事务。复制取消等待文件线程结束，已发布文件不回滚。list_artifacts 会检查文件存在性并保存删改状态，副作用标注为非只读。真实进度变化提升业务版本，只有观察时间变化保持原版本。

### 启动恢复与统一收尾实现（9.6）

由 Lifecycle 协调器先执行接收恢复、事务重建生成占位及阶段、调度预算核对、产物发布恢复、清理待办扫描；全部成功后才发布发现信息并启动后台工作。相比各循环自行恢复，此顺序避免派发早于占位重建，以及正常下载 intent 被笼统冻结。仅无可靠远端 ID 的提交标未知；已持久化 ID 的正常任务接续查询，原 needs_attention／abandoned 不复活，身份不兼容保留占位。

协调器跟踪派发、查询、下载、清理循环与其内部工作；draining 后禁止新工作，在同一收尾期限内等待，期满取消 I/O 并等待短事务／文件句柄安全释放。取消不擦除提交、下载或清理 intent，下次按阶段核对。生产构造不安装适配器；测试直接注入合成适配器，不增加环境变量或工具后门。

### 上传单次传输的离线实现边界（8.3）

先交付独立内部 upload_once 与上传响应解释器，通过既有 NetworkPolicy 发送 multipart file；不接入生产调度、不开放任意上传 MCP tool。调用方必须持有已登记副本的读取租约与锁定句柄；单次组件核对大小／摘要并复位句柄，不重新打开任意路径。相比先接通自动上传，此拆分允许验证真实 multipart 字节和解析，同时保留未完成的持久化预算、临时引用替换、清理竞争及重启接线。网络错误不在该组件内重试；后续由持久化协调器管理有限预算，不能因上传重传而重提已可能接单的生成。

上传 URL 不在 repr／错误中暴露；只保存响应实际提供的 expires_in，不缺省补 24 小时，不把该值直接解释为确定到期时刻。文件名采用内部固定媒体后缀，不外传本地原文件名。限制采用调用方已核对的字节上限，不把通用 50MB 当作模型适用性证明。

### 上传持久化与调度接线（8.3）

复用 uploads 的每素材／连接身份记录及 attempts 的逐次 upload:<material_id> 意图；预算初始化为首次尝试加 UPLOAD_RETRIES，发送前原子扣减并登记退避时间，重启和已知到期重传不重置预算。成功同样消耗一次尝试，防止短期链接持续过期导致无限上传。失败只对显式临时网络／429／5xx 有限重试，其余转待处理。不同于内存重试循环，此方案保留中断后的消耗和历史，不增加数据库 schema 或隐式迁移。

上传服务使用已登记素材、统一读取租约和锁定句柄，接收记录保留后缀以构造内部文件名；旧记录缺后缀明确待处理。临时 URL 仅在发送 payload 的副本替换 material_id，不改固定有效参数、请求摘要或用户外部 URL。expires_at 是本地保守复用截止（上传开始时间加实际 expires_in），不是上游精确到期保证；期限缺失转待处理，不补默认24小时。时间回拨不延长引用复用。提交事务复核绑定、ready、截止和素材可用性；已产生生成 intent 的任务不可因链接过期重传或重提。

Scheduler 可注入 UploadService 并在启动时恢复未结束上传意图，生产默认仍没有完整供应商适配器。准备和上传均受现有 Host/存储/并发门控；清理取消读取者并等锁定句柄关闭后才删除。未完成上传的迟到事实不得让已放弃／已取消任务恢复自动执行。

### 四样例提交／查询适配接线（8.4 部分）

新增内部 CompatibilityAdapter，复用统一 NetworkPolicy 与 decode_response；只发送固定兼容路径，不切换 /v1/videos，不重试生成 POST。prepare 使用已接收的有效参数副本，不重新计算默认值或优化授权，未替换的本地素材标识拒绝发送。查询 ID 限制为安全单路径片段（字母、数字、下划线、连字符），超出目前样例可安全处理的范围明确拒绝，不让供应商返回的 ID 改写路径。

HTTP 2xx 仅表示进入 JSON 解码的本地传输分类，不是接单证明；其他状态按既有保守分类，网络超时不构造未创建证据。解析器仍拒绝 SUCCESS 封装且不读取费用。四种已确认状态、关联 ID 和 metadata.url 经调度器持久化；缺 URL 保留生成成功并待处理。完整产物集合／尾帧契约未齐时，适配器的 artifacts 明确门控，调度器记录待处理而不是让后台循环因异常退出。选择先接通已确认主链路而不猜测完整响应；生产入口仍不自动装配本适配器，所有验证只使用合成传输。

兼容适配补充：API提交／查询拒绝HTTP重定向，避免服务端重定向将兼容路径切换为其他端点；下载等既有逐跳策略不变。失败白名单error_code纳入持久化观察和查询摘要，不保留原始message。

### 已确认主视频与未知完整集合（交付接线）

CompatibilityAdapter可读取数据库内已关联且无终态冲突的completed观察，提取metadata.url对应的主视频引用。新增内部ArtifactManifest将references与complete分开；完整集合未知时complete=false，注册事务把集合状态保存为task_events，不改schema、不因重启丢失。相比等待尾帧契约后才下载，此方案允许先交付已确认视频，同时不宣称全部必需产物已就绪。

ArtifactService逐个登记、下载、核验和复制已知视频；集合未知时任务delivery最多为partial，保留ARTIFACT_SET_UNVERIFIED，不settled、不触发artifacts_ready素材清理。异常名单显示未知集合，但不阻止已知视频的下载或显式恢复。重复查询／恢复不会清除该事实。此前已提供完整集合的合成适配器仍按原规则完成和清理。

容器格式只依据明确output_format或URL路径的mp4/mov后缀，不从签名查询串猜测；两者冲突或均无可靠格式则待处理，实际下载仍做容器校验。生产入口仍不自动启用真实供应商，尾帧／完整集合／SUCCESS／费用完整响应继续待核实。


主视频启动恢复补充：仅当原auto_mode为active且remote_state为succeeded时，ARTIFACT_SET_UNVERIFIED作为非阻断的集合说明保留，不将其单独升级为needs_attention；其他待处理原因仍阻断，原needs_attention／abandoned不复活。避免通过清除集合说明恢复下载，否则会误报完整交付。


### 清理持久化故障的生命周期保护补充

后台worker抛出StorageError且数据库已置storage_fault时，协调器保留只读RPC与健康查询，停止新副作用；不自动清除故障或用内存结果补记成功。相比直接退出后端，此行为保持既有本地可观察性。非存储故障或未触发存储保护的异常仍传播，避免吞掉编程错误。重新启动时按原清理记录和文件存在性核对，不重置预算。


### 存储故障下工具入口统一拒绝

Tools handler在调用非READ_ONLY工具前检查storage_fault，明确返回STORAGE_FAULT；只读白名单继续提供带stale标记的状态。相比仅依赖各子服务写入门控，此检查防止能力检查先返回其他错误而掩盖存储阻断原因。它不替代数据库事务和副作用执行前的检查，不能消除检查后的故障竞争，也不允许工具清除故障。

按请求标识只读找回的响应也包含stale，直接反映数据库存储故障标记，覆盖已接收、接收中和未找到结果；保持原找回响应字段及只读语义，不以缺失结果推断可重新提交。

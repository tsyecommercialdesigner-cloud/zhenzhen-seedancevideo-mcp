# Design

## Context

现有生产适配器保存 `complete=false`，下载汇总将其保持为 `delivery=partial`，历史任务可复制主视频，但 stage 常为 downloading。完整集合、尾帧跨模型和上游恢复契约仍待核实；旧规范要求保留异常记录及托管输入。当前任务库 stage 有固定 CHECK 枚举，错误码目录未覆盖部分业务异常。

## Goals / Non-Goals

**Goals:** 让 Agent 区分已发现产物已就绪与仍在下载，取得真实业务错误和安全动作，统一三款 Host 名称并简化默认配置；保留已有客户端和历史任务语义。

**Non-Goals:** 不推断供应商集合完整、不增加用户确认完整集合或素材清理操作、本次规划及隔离验证不请求真实供应商、不重新生成、不扩大真实 Host 验收结论。

## Decisions

### 附加展示状态

保留数据库 stage、delivery 和集合事件，增加 `display_stage`。在同一事务快照中仅当远端成功、集合未核实、已登记产物非空且全部登记产物状态 ready 时返回 `downloaded_unverified`；其余返回原 stage，并结合现有 delivery、auto_mode、attention 和产物状态展示真实故障或放弃。查询、按请求标识找回、分页和有界等待使用同一派生逻辑；非已接收的 receiving/not_found 结果不伪造展示状态。状态基于持久化记录，不暗示文件未在外部发生变化；外部检查仍按现有验证工具规则。

替代方案是在数据库引入新的 stage 并迁移所有历史任务，或直接标记 settled／ready。前者破坏旧枚举和恢复逻辑，后者虚报集合完整且可能提前清理；附加字段兼容旧客户端，不需要迁移。产物状态落账变化须已有业务版本推进并唤醒 wait；只计算新字段或重启本身不增版本、不重放副作用。

### 提示与可处理异常

保留旧 `attention`、`needs_attention` 和 `attention_count`，另提供 `advisory_reasons`、`actionable_reasons`，服务状态提供按任务去重的 `actionable_attention_count`，分页查询增加 `actionable_only`。仅当上述已就绪条件成立时将 ARTIFACT_SET_UNVERIFIED 分到提示；其余原因及尚未就绪时的异常不降级，未知原因保守归可处理。两类原因可同时存在，故任务可同时出现在提示与可处理统计中，计数是任务数而非原因数。新筛选纳入游标签名，仍不承诺跨页快照；无须清除历史异常。

`allowed_actions` 不再因 partial 单独推荐无目标的重试：已发现产物均 ready 时给出 list_artifacts、verify_artifact 和 copy_artifact 等适当动作；确有失败、缺失或可恢复下载时继续保留下载恢复。旧参数和既有异常列表仍可用；不把提示计数当成供应商健康检查。

### 业务诊断

采用静态白名单映射业务错误码、阶段、摘要及动作。PROMPT_AUTHORIZATION_REQUIRED 指向单次 allow_once 或共享偏好的查询／明确授权设置，先有用户同意；TASK_NOT_FOUND 指向本地检查或按原 request_key 找回，不推断远端不存在；已知不适用字段逐字段选择固定名称。未知异常保留 INTERNAL_ERROR，未知任意键、值、路径、URL 和原始堆栈不回显；持久诊断反查复用相同规则，旧记录安全回退。

对外层错误码也使用静态标识集合：保留代码中既有固定业务错误码和参数诊断码，未知异常文本即使符合大写格式也不透传。新增业务错误码时须显式更新该集合并补充兼容测试；不能从运行时异常文本自动扩充集合。相比仅判断异常文本格式，这一边界避免把任意密钥或提示词当成错误码。

可信边界同时检查已知内部异常的确切类型和静态错误码；直接使用内置异常的业务拒绝改用专用内部异常子类，仍保持原有 ValueError／RuntimeError 捕获兼容。无专门文案的已知公开错误码使用固定的通用脱敏诊断，确保反查与外层码一致。与按文本推断来源相比，这要求维护异常类型和码表，但未知异常不能冒充业务错误。

维护码表时还须核对通过模块常量、条件表达式、异常转换、默认参数和返回值构造的固定码；静态覆盖不得只扫描直接 raise 字面量。上游任意错误码不因此自动成为可信码。供应商查询调度可能自行捕获适配器异常并保存状态，诊断验证应区分处理器透传与该实际调度路径。

先检查异常的确切类型，未知类型不读取其属性或调用字符串转换；可信类型的码提取失败也安全回退。诊断阶段以静态工具操作映射为基础，参数／授权校验和存储故障分别优先标记 validate 和 storage，查询、接收、提交、下载和清理操作分别使用对应阶段；持久化记录与反查使用同一阶段。

### 默认执行模式与检查隔离

代码默认值和新 `.env.example` 均采用 provider；保留安装目录 .env 优先、缺失才回退进程／用户环境变量的规则。已安装 `.env` 显式 local 继续生效，升级不自动覆写；模式完全缺失时新默认生效。启动 provider 可恢复已有明确授权的任务，可能产生网络请求；旧 local 接收或无执行授权任务继续按已有保护停住，重复 request_key 不补授权。新的 provider 正式提交由原有机制自动执行、可能收费，预检或启动本身不创建新任务。

协议检查改用独立临时安装配置根、临时用户状态和占位凭据，显式 local，并排除继承的业务密钥和与配置冲突的环境变量；测试须证明安装目录真实 .env 的优先级不会覆盖检查隔离配置。检查只发现工具和调用只读工具，不接入或停止真实共享后端、写入真实任务库、发起供应商请求或修改 Host／真实 .env。报告本地协议结果，不把检查通过当作上游可用。相比要求用户先切 local 再改 provider，此方案减少配置步骤且维持无副作用检查；单纯覆盖进程环境变量不足以绕过安装目录 .env 优先级，不能采用。

### Host 命名与兼容

Codex、Claude 的 Host 配置键、DSH 的插件 id 与 serverName 和 MCP initialize 服务名称统一为 `zhenzhen-seedancevideo-mcp`；实际命令 `zhenzhen-seedance-video`、API 标识 `seedance-video`、Python 包、任务库和供应商模型 ID 不重命名。仅更新示例和迁移说明，不自动重写用户配置；提示先核对并移除旧别名对应项以避免重复注册。实际 Host 验证需另行确认环境和权限，不将配置示例视为已验收。

### 验证与文档

隔离测试覆盖常规、超分、多产物、历史库、跨 Host、异常混合、重启、外部删改、并发版本及无副作用；诊断覆盖单次／共享授权、缺失任务、非法字段、注入及敏感信息。更新 Agent 工具说明和实际验证记录，不将合成测试冒充真实上游或实际 Host 验收。

## Risks / Trade-offs

- [旧客户端继续看到 downloading 和旧 attention_count] → 新字段提供精确解释，文档说明旧字段兼容语义；不能强制旧 Agent 使用新字段。
- [派生信息与并发状态不一致] → 读取同一数据库快照；有界等待只依赖业务版本，避免额外副作用。
- [素材长期保留] → 如实显示集合未核实及保留原因；本次不改变清理边界，后续经证据或单独决策处理。
- [Host 提前验证或隐藏新增字段] → 实际 Host 展示保留未验收标记，隔离协议测试不替代 Host 证据。
- [默认 provider 会使新提交产生真实费用，且启动可能接续已授权任务] → 显示当前模式和付费语义，保持历史授权、去重及恢复保护；本变更验证使用合成适配器与隔离 local 检查。
- [旧安装显式 local 不随默认变化] → 尊重配置优先级，手册说明如何手动改为 provider 及安全重启，不改用户配置。
- [服务名称变化影响按名称匹配的 Host] → 保留命令和 API 标识，提供旧名称迁移和防止重复注册说明，按 Host 分别验证。

## Migration Plan

升级后从现有持久化事实派生字段，既有任务无需批量写入或强制迁移；多 Host 使用相同后端版本。显式 local 保留，缺失模式按新默认 provider；升级及回滚不覆盖用户 `.env`，不同模式配置冲突按既有规则处理。回滚到旧版本时新增展示字段消失，缺失模式按旧版本默认 local，原数据库及状态语义保持不变；任何跨版本连接仍遵循原有兼容检查。

# Design

## Context

现有 MCP request 为无字段的 dict；后端规范化负责模型差异、未知字段及安全校验。此前供应商证据和默认行为不变。

## Goals / Non-Goals

目标是让工具能发现字段、纠正输入并理解预检。非目标是新增估价、改变供应商行为或运行收费调用。

## Decisions

- 使用类型化结构描述输入的联合字段，由服务端继续判定各模型适用性；避免用统一必填 prompt 错拒成片与超分。相较仅写长文档，Schema 可被 Host 直接发现；保留字符串 URL 与本地路径输入。
- 在校验层产生静态字段名、类型提示；诊断白名单只接受受控元数据，不透传原始请求。保留现有顶层 error，并补充精确诊断。
- 预检保留 authorization 和 estimated_charge，增加明确语义、音频来源及未知费用说明。相比重命名或改变默认值，兼容现有调用方。
- 执行授权说明区分 provider 接收和 local 接收，沿用旧任务跨模式不自动获得供应商执行授权的既有边界。
- 联合 Schema 不使用可能被 Host 自动注入的上下文相关 `default`：音频默认只适用于常规模型，优化默认还受共享授权影响；以说明文字及实际预检结果表达。素材条目按类型声明相应嵌套 URL，防止 Schema 将缺少相应素材的对象视为有效。
- 参数类型错误与字段缺失、值不支持分开报告；保留稳定业务错误码并使用白名单诊断字段，不回显接收到的值。已发布的 Schema 可被 Host 提前校验，不能保证所有 Host 均调用到后端诊断。

## Risks / Trade-offs

- Schema 描述跨模型联合字段 → 按模型能力查询和服务端校验限定实际适用性。
- 框架提前校验可能改变错误格式 → 隔离协议测试覆盖有效输入及错误路径。
- 参数错误不得暴露任意字段或值 → 对可展示字段使用白名单。

## Migration Plan

兼容原请求形状及返回字段；无需迁移任务数据。若回滚代码，新增说明字段不再提供。

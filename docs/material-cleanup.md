# 托管素材清理与恢复

清理只作用于数据库登记的输入托管副本；用户原文件、生成视频、交付副本及任务历史默认保留。retry_material_cleanup 工具已接线，Agent 调用见 agent-tools.md；以下保留内部 CleanupService 接口说明。

## 触发与保留

以下事实与清理授权在同一事务保存，不设保留期：全部必需产物 ready、明确生成失败、提交前本地取消、已可靠确认的上游取消，以及明确放弃跟踪／下载。后端清理循环处理持久待办，启动时补齐符合条件但尚未登记的任务。

生成结果不明且未放弃、仍生成中、生成成功但下载未完成或待恢复的任务保留输入。明确放弃后即使远端结果仍未知，也清理副本，保留远端 ID 和事实；不冒充生成失败或取消。后来仅查询或下载无需恢复输入，但重新生成须重新提供素材。已持久化的清理授权不会被后续刷新或恢复悄悄撤销。

样片 ready 后不为将来可能的成片保留输入，样片任务 ID 和视频仍在。以已有生成视频进行超分时，只删超分任务自己的托管副本，不删原生成视频。上游取消能力仍待核实；清理条件不代表已支持真实取消接口。

## 读取竞争与删除边界

上传准备、素材修复共用每任务读取协调器。清理先阻止新读取，设置线程停止信号并取消旧异步操作，等待文件句柄释放；超时仍有读取时明确记录忙碌，绝不并发删除。适配器中的文件线程必须使用协调器提供的 thread 包装，取消必须等待真实线程结束，不能只取消 await 后遗留读句柄。

删除仅接受登记 material_id，不接受用户路径。要求路径严格等于固定托管根中的 material_id.input，拒绝链接、目录和越界；目录祖先持有禁止删除共享的 Windows 句柄。文件以独占读／删除句柄打开，检查内容摘要和大小后对同一文件句柄标记删除，关闭时删除。不递归清空目录，不触及外部链接目标。文件已不存在可补记 cleaned，不要求重新提供文件。

## 预算与恢复

cleanup_jobs 保存 new／pending／deleting／done／failed、剩余预算、下次时间及稳定错误码。首次处理固定“首次尝试 + CLEANUP_RETRIES”，每次删除前持久化消耗；退避最多 60 秒。重启保留预算，deleting 状态恢复时已不存在可补记完成；零预算且文件仍在只能报告耗尽，不能再删。错误只影响清理状态和待处理原因，不改生成终态或删除已有产物。

持久化失败前不新增删除。删除后落账失败保留 deleting，恢复核对不存在后补记；任务库故障遵循统一存储保护，不重建空库。失败诊断返回代码，不包含原始异常、路径内容或堆栈。

| 代码 | 处理 |
| --- | --- |
| CLEANUP_FILE_BUSY_OR_DENIED / MATERIAL_READERS_BUSY | 等待占用释放或修复权限；预算内重试 |
| CLEANUP_OWNERSHIP_INVALID / CLEANUP_UNSAFE_FILE / CLEANUP_PATH_OR_IO_ERROR | 核对登记与存储环境，不绕过路径保护 |
| CLEANUP_CONTENT_CHANGED | 托管副本与登记摘要不一致，保留文件待处理，不删除未知内容 |
| CLEANUP_RETRIES_EXHAUSTED | 修复原因后显式重试 |
| MATERIAL_CLEANUP_FAILED | 任务级清理异常提示；不表示生成失败 |

内部恢复示例：

```python
state = await task_state.get(task_id)
await cleanup.retry(task_id, expected_version=state["version"])
await cleanup.due()
```

retry 只重置已有失败清理待办，保留历史事件；没有清理授权的任务拒绝。重复请求不重复排队，版本冲突需先重查。调用不保证立即删除成功，须读取任务 cleanup_state 和清理待办结果。不存在任意路径删除工具。

验证见 tests/test_cleanup.py，以及接收、调度和 Windows 后端回归；使用合成文件和事实，不调用供应商。真实上传、取消响应、SUCCESS 和费用完整封装继续待核实。

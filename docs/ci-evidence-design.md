# CI 发布事实回填与证据复用设计

状态：本地实现及隔离验证中；实际 GitHub 门禁和远端分支保护仍需在提交后的 PR 中验证。

项目特例：用户指定 `MANUAL.md` 的内容由 Agent 和人工审查，发布后回填分类跳过该文件的 CI 内容检查，状态报告明确披露未自动审查；不得跳过其他文件或 Release／复用证据核验。手册包含在源码包中，手册变更后不能复用旧源码包；发布候选的完整验收不因本特例豁免。

完整检查必须绑定实际受检 Git 提交、源码及测试输入、检查脚本和工作流、锁文件、工具版本、操作系统与 runner 镜像，并以受信任的 CI 执行结果和保留期内的证据证明其成功。候选包另须绑定实际打包输入，不能仅凭运行时源码一致复用包含已修改文档的旧包。

轻量回填仅覆盖经确认不影响构建或运行决策的已知事实：README 的固定格式版本段，以及资源清单中精确结构的已发布资产记录；自由形式验证记录保守回退完整检查。资源清单虽随 sdist 分发，但当前没有被构建或运行时代码读取为决策输入。未知字段、命令、路径、代码、配置、依赖或无法确认的用途均须保守归入完整检查。轻量路径检查适用格式、JSON、链接、秘密，并与真实 Release 核对标签、完整提交和资产摘要；MANUAL 按上述用户特例人工和 Agent 审查。

备选方案是直接依据扩展名或 PR 描述声明轻量变更；两者不能证明用途或证据来源，不采用。复用须验证证据由本仓库受信任的已成功工作流产生、绑定已合并来源且未过期，并核对相关输入、工具版本和运行环境；不可读取 PR 自带的声称结果作为证明。`windows` 检查保持稳定名称并报告轻量或完整范围；证据／API 不可用或存在不明确变更时回退完整检查，已识别的 Release 事实冲突则失败。首次部署或旧 CI 不含证据时执行完整检查。复用仅涵盖检查结果，不复用旧候选包。

资源清单的轻量路径只接受追加精确结构的已发布 wheel／sdist 资产记录：`path` 为当前仓库对应 Release 资产下载 URL、`version` 为实际标签、`sha256` 为实际资产摘要，`purpose`、`task`、`owner`、`status`、`release_condition`、`cleanup` 分别使用分类器中声明的固定值。既有记录不能改写；临时资源、自由文本和其他结构继续执行完整检查。此限制不改变资源清单的正常记录格式，只限制可自动判定为轻量回填的子集。

# CI 发布事实回填与证据复用设计

## 2026-11-16 调整设计（待实施验证）

按审阅通过的工程规范调整：同一 PR 取消过时运行；MANUAL 单文件轻量路径补充格式、链接与秘密检查，事实由 Agent 和本人对照实际 Release 审阅；仅凭路径不能证明事实回填，无法确认时回退完整检查。日常非运行输入变更应按用途选择检查，未知或执行输入变化保守处理。完整候选验证可复用同仓库可信历史检查，但必须验证范围、输入、工具及环境，缺证据补做；打包输入变动不得沿用旧包。正式发布由显式受控入口核验 main 提交、标签、资产与来源后发布，标签推送本身不触发。候选资产缺失时从确认提交重建并验证，失败停止。远程工作流、发布及分支保护实际状态须分别验证，不能仅以此设计视为已部署。

受控入口拟采用只允许 main 手动触发的 GitHub Actions workflow；用户提供确认的 main SHA 和已完成的发布候选运行 ID、发布说明及预发布标记。以 GitHub API 和候选产物验证 PR 来源、运行结论、实际受检树、资产摘要及版本；候选运行复用检查时记录原运行 ID 并核对其可信证据。原资产已明确过期或不存在时，在 main 干净 checkout 重新执行完整检查、构建和安装验证，再生成新摘要；无法确认身份或 API 异常则失败停止。只在核验完成后创建 draft Release 并上传，核对远端标签与资产后发布；失败保留 draft 供核对，不自动覆盖或删除已有标签和资产。发布授权是执行该入口前提，当前实施及隔离验证不触发真实发布。

实际入口为 `.github/workflows/release.yml` 的 `workflow_dispatch`，仅允许从 main 发起，要求输入完整 `main_sha`、已合并 dev → main PR 的成功 `candidate_run`、发布说明、预发布标志和已核对人工验收的确认。准备 job 只有读取权限，发布 job 才获得 contents 写权限；在候选资产齐备时核验来源与摘要，分别安装源码包和 wheel 并进行 local 协议检查；候选或复用证据明确过期时重新检查、构建及安装。创建标签前确认 main 和已存在标签／Release；先创建标签再创建草稿，以实际 GitHub 标签行为为准；资产摘要核对后发布并复查。失败时保留已产生的标签／草稿，不自动删除或盲目重试。

只读核验 PR #15 时发现，按 dev 分支头提交查询关联 PR 可能返回合入 dev 的 feature PR；受控发布改为按实际 main 合并提交查找关联 PR，再核对 PR 的 head 和 CI 运行身份。此核验未创建标签或 Release。

当前增加 PR 并发取消，单手册轻量路径接受普通文字修改，代码围栏和标题修改回退完整检查；检查差异空白、常见秘密模式及变更行中的本地链接。这种结构检查不证明内容是发布事实，仍须 Agent 和本人核对。仅 dev PR 使用文档分级，范围仅限既有允许路径的 Markdown 修改，检查语法围栏、仓库内链接、diff 和秘密模式；仅修改既有独立测试文件时执行 Ruff 和受影响测试，其余代码保守执行完整检查。main 候选可复用可信历史完整检查，要求候选文件树完全相同、验证器来自可信基线或已集成且与候选对应的 dev、环境输入一致；复用时仍在本次构建候选包，并区分本次构建与复用检查的证据。无法核验则完整检查。手动发布入口及资产过期重建路径已在实现中；实际远端发布、分支保护和工作流行为尚未验证，不得据此宣称规范已全部落实。

状态：本地实现及隔离验证中；实际 GitHub 门禁和远端分支保护仍需在提交后的 PR 中验证。

项目特例：用户指定 `MANUAL.md` 的发布事实由 Agent 和人工审查，状态报告明确披露 CI 未核验事实；涉及其他文件时仍须进行适用的 Release／复用证据核验。手册包含在源码包中，手册变更后不能复用旧源码包；发布候选的完整验收不因本特例豁免。

仅修改已有普通文件 `MANUAL.md` 的普通文字时，在本地标签能证明对应发布提交已进入 main 且其发布来源包含于当前分支时，由预检检查改动并声明人工／Agent 审查、未运行测试和未生成产物；事实性质由人工与 Agent 核对，CI 不对此作保证。代码围栏和标题、标签或分支关系不可确认、同时存在其他改动、文件类型变化或非 PR 触发时回退完整检查。其他回填的 Release 核验支持 main 上的发布合并提交及其来源分支，不要求该合并提交自身是 dev 的祖先。

完整检查必须绑定实际受检 Git 提交、源码及测试输入、检查脚本和工作流、锁文件、工具版本、操作系统与 runner 镜像，并以受信任的 CI 执行结果和保留期内的证据证明其成功。候选包另须绑定实际打包输入，不能仅凭运行时源码一致复用包含已修改文档的旧包。

轻量回填仅覆盖经确认不影响构建或运行决策的已知事实：README 的固定格式版本段，以及资源清单中精确结构的已发布资产记录；自由形式验证记录保守回退完整检查。资源清单虽随 sdist 分发，但当前没有被构建或运行时代码读取为决策输入。未知字段、命令、路径、代码、配置、依赖或无法确认的用途均须保守归入完整检查。轻量路径检查适用格式、JSON、链接、秘密，并与真实 Release 核对标签、完整提交和资产摘要；MANUAL 按上述用户特例人工和 Agent 审查。

备选方案是直接依据扩展名或 PR 描述声明轻量变更；两者不能证明用途或证据来源，不采用。复用须验证证据由本仓库受信任的已成功工作流产生、绑定已合并来源且未过期，并核对相关输入、工具版本和运行环境；不可读取 PR 自带的声称结果作为证明。`windows` 检查保持稳定名称并报告轻量或完整范围；证据／API 不可用或存在不明确变更时回退完整检查，已识别的 Release 事实冲突则失败。首次部署或旧 CI 不含证据时执行完整检查。复用仅涵盖检查结果，不复用旧候选包。

资源清单的轻量路径只接受追加精确结构的已发布 wheel／sdist 资产记录：`path` 为当前仓库对应 Release 资产下载 URL、`version` 为实际标签、`sha256` 为实际资产摘要，`purpose`、`task`、`owner`、`status`、`release_condition`、`cleanup` 分别使用分类器中声明的固定值。既有记录不能改写；临时资源、自由文本和其他结构继续执行完整检查。此限制不改变资源清单的正常记录格式，只限制可自动判定为轻量回填的子集。

# 素材上传与持久化准备

上传服务在本地任务接收之后、生成提交意图之前执行。`UploadService` 通过 Scheduler 的内部 `uploads` 参数接入；隐藏后端可通过内部 `upload_factory` 注入。生产入口仍未装配完整供应商适配器，不能据此宣称真实生成闭环已就绪。

## 预算与恢复

每个托管素材和连接身份对应一个 uploads 记录，首次固定 `1 + UPLOAD_RETRIES` 次尝试。每次先在同一事务扣预算并写 attempts 意图与下次可尝试时间，再通过存储副作用门发送。失败只对明确临时的网络错误、429、5xx 退避重试；鉴权／权限、非法响应、素材不可用等直接待处理。配置后改或重启均不重置已记录预算。

上传开始后进程退出，恢复协调将旧上传 intent 标为 reconciled，保留已消耗次数和退避。新上传只用于仍未提交的任务；从未把上传中断当成生成已创建，也不会因此重新发送结果不明的生成请求。有限停机取消上传时句柄在退出读取上下文前关闭。

## 临时引用

固定任务参数仍保存 material_id，稳定请求身份仍由原素材摘要决定。临时 URL 只替换发送 payload 的副本；用户外部 URL 不下载缓存，不自动替换。上传成功保存 URL、实际返回的 file_type/size/expires_in，输出摘要和异常不暴露签名 URL。

本地 expires_at 使用上传开始时间加实际 expires_in 作为保守复用截止，并非供应商精确到期承诺。缺失期限转待处理，不补24小时；回拨时钟转待处理。已知过期只在未提交阶段重新上传相同摘要副本，也消耗剩余预算，不因成功过期而无限重传。

所有素材准备完成后，生成提交事务再次核对引用 ready、连接身份及截止时间；不合格不创建生成 intent，下轮在预算内重新准备。已提交／远端未知／取消／放弃任务不会获得新的上传许可。部分素材已成功时复用其未过期引用，仅推进其余素材。

## 文件与清理协调

接收事件保存上传需要的后缀，不保存或发送原本地文件名；上传内部文件名为 material 加已知后缀。此前接收且缺少后缀的任务不会猜测类型，上传转待处理。后缀支持不等于模型支持该素材，仍需模型参数校验。

上传只访问本任务登记的 materials 目录副本，核对托管文件名、摘要和大小，使用锁定句柄与共享 MaterialReaders 租约。放弃／取消后的清理先取消上传读取并等待句柄关闭，再删除已登记副本，保留用户原件。迟到上传响应不会重新激活已放弃任务。
